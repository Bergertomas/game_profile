# ADR 0032 — Gate B profile direction

**Status:** Accepted · 2026-08-30

**Context:** the accepted Gate A A1/A2 Rev 5.1 direction; the 28 August
score/radar audit and Gate B brief; Fable **Should I Play - Canonical
Screens.dc.html** A3–A6; the 29 August candidate review; and Tomas's acceptance
on 30 August 2026.

## Decision

The Gate B A3–A6 screens are the accepted profile visual, information-hierarchy
and interaction direction:

- A3 — art-led desktop profile;
- A4 — art-led mobile profile;
- A5 — complete artless desktop parity state;
- A6 — complete artless mobile parity state.

The profile answers “Should I play this?” before methodological depth. Identity,
scope/build, platform identity, evidence state, one-line experience, Pull, Tax,
fit and practical commitment precede the full instrument. The radar is a
signature overview, never the only exact or accessible representation. Eight
permanent rows retain the fixed public order, exact value/range/Unknown,
confidence and a semantic disclosure path.

Art-led and artless states are content-parity variants. Missing artwork never
creates an empty hero, placeholder apology or reduced evidence/decision surface.

## Truthfulness requirements

- Fable artwork is private design material until it completes the lawful
  artwork path.
- Practical-time examples are layout specimens. Production renders approved
  scope-aware values, `Unknown`, or omits an optional summary; components must
  never fabricate a commitment band from the examples.
- The public meaning and source field for the label **Evaluated** remains an
  implementation copy/data decision. Do not silently equate it with
  `published_at`, `evidence_cutoff_at` or a new field.
- Material `platform_warning`, platform performance notes, subcriterion
  `platform_note` and platform overrides must project where they affect the
  public decision. The prior D3 promotion dropped part of this projection; Gate
  B implementation must restore it without changing base dimension totals.
- Exact values, confidence and Unknown/range semantics remain authoritative;
  no chart area or aggregate is introduced.

## Implementation boundary

Do not refactor the existing profile-wide client boundary as preparatory
homepage work. Revisit it only inside the Gate B implementation slice, where
the accepted component/source-order requirements and bundle impact can be
tested together. Interactive leaves should be narrowed only when the refactor
is directly justified by that implementation and preserves current behavior.

## Non-blocking follow-up

A7's older token card is not authority. The shared design-system/interaction
handoff reconciles A1–A6 tokens, responsive states, focus behavior and reduced
motion. The missing Fable background-verifier message remains a recorded tool
gap; the candidate was accepted on its self-check, independent inspection and
owner review, not on a verifier result that never appeared.

## Consequences

- Gate B is closed; profile rediscovery stops.
- The accepted screens authorize implementation, not publication of specimen
  time, private artwork or unresolved destination/evidence records.
- The dedicated full Compare design pass and shared handoff follow Gate B.
  Within engineering, Search implementation moves before full Compare
  implementation.
- Visual-conformance and accessibility review compare production against A1–A6
  after the relevant surfaces are implemented.
